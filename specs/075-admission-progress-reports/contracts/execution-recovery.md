# Durable Admission Execution and Recovery (Proposed)

## Ownership and prerequisite

API owns accepted admission commands, producer execution, report materialization and notes scheduling. Git owns verified publication/source receipts; spec 074/#139 owns retained source capture/replay. Existing callback, source replay and GraphQL committed-manifest paths converge on one internal command boundary; no API/controller worker protocol and no public report create/status mutation. Reports, diagnostics, operational Events and audit evidence are not the work queue. Normal pushes synchronously await the required post-receive admission outcomes while the API streams progress; background worker ownership keeps accepted execution recoverable if the waiting client disconnects. The execution context is independent of the waiting request context.

Extend actual write/callback results additively with a shared AdmissionSourceReceipt containing repository UID/epoch/sequence/mutation ID and exact old/new ref transition; use the same canonical receipt when #139 contracts integrate. Normalize Git wire zero OIDs to absent old/new receipt fields, matching source 074; digest canonical source facts, not presentation strings. New-path committed ref results require the verified matching receipt and uncommitted refs cannot carry one. Do not independently regenerate two transition IDs. A stable write-operation key supports authorized LookupAdmissionMutation after response loss, backed by spec 074's retained operation/source index, bounded by its retention; NOT_FOUND/expired is not proof no effect occurred. Add signed operation_id at free field6 of CommitFileRequest/CreateTagRequest and field8 of DeleteFileRequest; CommitFileAtRevisionRequest inherits file.operation_id. Add source receipt field3 of CommitFileResponse/CommitFileAtRevisionResponse/CreateTagResponse and field2 of DeleteFileResponse. These numbers are free at baseline; recheck against concurrent canonical changes before merge and preserve existing numbers. New CatalogService.AcceptAdmission uses existing CallbackAuthorization and a matching source receipt, returns explicit accepted/existing root identity, and never implies semantic completion. Legacy AdmitResources forwards to the same boundary only on capable versions; never execute both independently. See catalog-accept.proto. GraphQL's service:system:api backing writer retains authenticated initiator proof separately; Git author/committer strings never authenticate the actor. SHA-only or unverified current-ref evidence cannot claim full durable acceptance.

Before activating durable execution, both #139's publication-to-source proof and this acceptance/effect protocol must pass their crash tests. Otherwise retain explicitly documented legacy behavior without advertising restart recovery. Source capture can precede execution rollout; never run the old detached executor beside a new independent source executor.

## Bounded command acceptance

1. Authenticate source/callback/GraphQL command authority and producer support. Verify full source receipt plus immutable digest; determine exact processing scope from original transition, not current projection existence. Normal committed inputs are accepted within 24 h of verified publication (or recovered from an already accepted root); older unseen roots require explicit operator recovery, not blind reacceptance after dedupe horizons.
2. Persist enumerable PREPARING recovery intent before creating canonical command IF NOT EXISTS. Root identity includes source/producer/phase/scope; same identity with different input conflicts. Existing root retains original metadata, authorization policy and result. Preparation data is bounded before acceptance; wrong/incomplete source identity is explicit unavailable/uncertain.
3. Read original revision/deletion identity through owned native Git access and materialize all needed immutable input pages/digests. Preserve push-set/category dependencies and exact old/new blob facts. Cap32 refs/push,5,000 selected manifest units and64 MiB selected input total/push,256 KiB/manifest,64-KiB transport chunks and configured finite pack limit (qualification512 MiB). Native pre-publication validation reserves source/input-capacity obligations or rejects before ref effects; already committed source obligations are retained/backpressured, never dropped because the API queue is full.
4. Seal immutable paged leaf/dependency manifest and recoverable per-ref root/report/batch creation intents. GraphQL subset and full source roots refer to the same semantic leaf/effect identity: source+producer/version+phase+canonical path/target incarnation+derived operation+old/new input digest. Scope/entry transport/root ID is not in the leaf effect key. Same content without a new write is a labeled reconciliation/no-op root linked to prior verified effect when possible, not a fabricated Git event.
5. Mark command ACCEPTED with manifest digest, exact original inputs/provenance, producer recovery policy and enumerable obligations. Only then advance the corresponding source consumer acceptance checkpoint. Report may still be QUEUED, but its real identity and materialization intent must be recoverable; public mutation success requires the returned concrete report row to exist. No accepted root relies only on a pointer to a Git object that repository deletion/GC can remove.

Cross-partition steps always persist intent before canonical acknowledgment, compare digests and roll forward after crashes. Orphan preparation cleanup first proves no accepted owner. No Scylla cross-table conditional batch is assumed. Apply report contribution+count/control updates in one same-table/partition CAS batch; indexes are repaired from durable intents and are never acceptance authority.

## Execution and target-owned effects

API background workers use bounded due scans<=256, select<=16 ready roots/batch and acquire root ownership through expected-version CAS,30 s lease/10 s renewal. Lease loss stops scheduling. Per API <=16 executing roots, <=32 concurrent producer leaf operations, <=256 queued wakeups. Durable pending quota 500,000 manifest units/16 GiB selected input fleet-wide; source acceptance backpressures at quota and preserves upstream retained obligations. Persistent allocation accounting is authoritative; process-local limits can only throttle earlier. Recovery repairs quota reservations; no unbounded detached goroutines.

Keep dependency waves/push-set ordering from existing catalog admission. Each leaf operation has <=5 s call budget; bounded safe reads/transient requests may retry<=3 times in30 s. Attempt execution deadline<=300 s after start; waiting for a dependency or observer does not extend it. Up to3 automatic attempts/root for verified infrastructure failures, max 10 total including explicit reruns. Deadline exhaustion stops scheduling and verifies unfinished effects; ambiguity remains PAUSED/nonterminal until reconciled, not falsely TIMED_OUT. Automatic recovery of an unfinished attempt keeps the same attempt/report identity.

Every enabled producer supplies this internal contract, with kind-specific backend conformance:

| Operation | Required proof |
| --- | --- |
| PrepareEffect | Capture expected target UID/resourceVersion and install target-owned source-order/fence binding only if the effect is applicable to that authoritative lineage. No old source can install a guard over a newer accepted target lineage. |
| ApplyIfExecutionCurrent | Atomically require the installed target binding, immutable effect/input identity and expected incarnation/version while mutating authoritative target and retaining its effect receipt. Create/name-claim, update and deletion have separate owner implementations. |
| VerifyEffect | Return Applied with immutable result/receipt, DefinitelyNotApplied with current safe retry preconditions, Superseded with proof, or Unknown. Current equal content/absence alone cannot prove an earlier execution. |

For Product/update the target fence/effect marker must participate in the same authoritative mutation condition as resource_version, not a preceding work-table read. If resource receipt/guard needs several rows, they must be within the target's supported atomic table/partition. Existing name-claim/create and UID/deletion/tombstone protocols must be extended at their real authority, not by a generic separate receipt. Deleted targets retain UID-bound receipt/tombstone evidence and cannot hand it to a same-name replacement. Index repair reuses existing mutation recovery after authoritative effect commit.

**Readiness gate**: current code does not implement this universal primitive. Each initial enabled catalog/RBAC kind must have a reviewed concrete backend commit/verifier and memdb/Scylla stale-write/crash tests. A kind/operation without proof is unavailable for automatic durable execution; a lease or callback nil error does not waive this requirement. This is specified implementation work, not an unresolved choice of guarantee.

An overlapping new root verifies/reuses completed leaves; explicit rerun never means repeat arbitrary external effects. Preserve full effect proof while any accepted/recoverable root references it and at least 7 d after terminal; retain closed identity/hash markers through 90-day report/source retry horizons. If detailed proof/input has expired, reject rerun/late alias acceptance with REPORT_INPUT_EXPIRED rather than treat a missing receipt as unapplied. Producer-version changes create a distinct execution under current authority, not silent alteration of an accepted root.

## Authorization policies and revocation

Ordinary catalog execution follows its owning current actor/target checks using verified recovery service identity plus original provenance. Committed RBAC projection is special: it completes its precommit-authorized whole candidate under the accepted candidate/projection proof; later actor revocation cannot veto that committed projection (`rbac.go`, `rbac_projection.go`). Do not convert this into general historical-actor authority. Record recovery policy/version with the command, and reject unknown producer policies at activation.

New submissions/reruns and every report/diagnostic/list/watch/export read require current authorization. Recovery is not subscriber export. Observer revocation/expiry detaches or reauthenticates within declared bounds; it never cancels accepted RBAC projection or grants another principal the report.

## Results and terminal reports

Replace callback empty-success inference with explicit typed per-leaf results: ACCEPTED/NO_OP/DENIED/FAILED/SKIPPED/UNRESOLVED plus canonical findings, effect reference and disposition. Missing dependencies, unresolved ref, failed namespace lookup and convergence exhaustion cannot count as success. Record every leaf decision/findings intent durably before idempotent report/batch contribution. Root processing acknowledges only sealed applicable obligations; partial multi-ref publication never invents children for uncommitted refs.

Publish running summaries at most once/s or per 64 verified leaf completions. Unknown effects keep unresolved count and conditions. Finalization verifies all planned contributions, preserves known failure counts even if findings are omitted, seals diagnostic snapshot/digest, and then CAS-publishes COMPLETED/conclusion. Duplicate completion after ownership/head progress returns the same immutable receipt; contradictory duplicate conflicts. Terminal attempt history is not overwritten by another attempt or status update. Internal retry counters/leases are not public desired spec fields.

## Rerun and rollback

rerunAdmissionReport requires admissionReport.create plus current original-source/target authority, durable required audit intent under the owning coverage policy when available, retained inputs/proof and stable caller key<=128 bytes. Until required audit coverage exists, enable the operation only with an equivalent recoverable owner audit-intent contract; otherwise fail AUDIT_UNAVAILABLE. Under root CAS reserve the next ordinal, persist recoverable report/work intent and materialize QUEUED report before returning. Request-key replay returns that attempt; contradictory reuse conflicts. Pending attempt may be resumed, not cloned concurrently; maxone active attempt/root.

Roll out store/owner guards/shared receipts first, callbacks and source ingestion in converged mode next, then report observation/streaming. Drain incapable replicas and use explicit deployment feature routing until spec 072 capability floors exist. Preserve source/work/input/closed markers on rollback; do not route accepted new-contract work to old executors. No destructive down migration, automatic new producer or duplicate legacy callback engine.
