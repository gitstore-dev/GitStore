# Git Streaming and Attached Observation (Proposed)

## Additive RPC and upload boundary

Merge proposed messages in git-stream.proto and add ReceivePackStream bidi to the existing GitService; leave ReceivePack cardinality/field numbers unchanged. New-path data is typed, not pre-sideband-encoded bytes. API is the sole new-path pkt-line encoder. Existing receiver/method/request-bound signed metadata authenticates the entire first frame; PushContext.authorization remains the approved action/actor decision. Validate matching repository IDs, current supported policy/config revision and allowed capability set. Later frames cannot change these facts; adapters/tests must teach the existing signing/verification dispatch this new full method rather than omit authentication.

Sequence: exactly one Begin (<=32 complete RefCommands and <=4 KiB capability tokens), zero or more Data frames<=64 KiB, exactly one End with verified byte count, then client CloseSend. EOF/cancellation before End is incomplete upload, including delete-only Begin without End. Reject repeated Begin/End, unknown frame variants/version, excess bytes or data after End. Delete-only sends Begin+End with zero bytes and no invented PACK. Pack512 MiB qualification ceiling, selected manifest256 KiB/file/64 MiB total and5,000 units/push are finite deployment policy, not new unbounded defaults.

Sign/verify first-frame freshness/replay protection using the existing RPC envelope; do not weaken its timestamp window. After acceptance, the session has a120-second maximum upload/publication budget, bound to that repository/operation and disconnected-upload behavior. The request authorization is not a bearer credential for later work. Current owning pre-publication checks still apply; if more input/time is needed, reject before ref effects. Admission observation uses separately current API authorization after this RPC completes. A stalled RPC/HTTP observer cannot keep publication locks indefinitely.

Events have monotonically increasing per-session ordinals. Emit bounded numeric indexing/validation/publication progress and canonical sanitized pre-receive findings (not arbitrary log strings), followed by exactly one PublicationResult on a known outcome. That result has actual unpack/per-ref publication facts and shared source receipts, never admission success. A lost result is an uncertain observer outcome and uses authorized operation/source lookup; it is not an instruction to push again. A publication_uncertain result requires all known per-ref facts plus explicit uncertainty; no fabricated ng/ok for unknown refs. Native source recovery is authoritative.

Before flushing Smart HTTP, API consumes the entire bounded request body and completes parsing. Read gRPC events concurrently to avoid deadlock/backpressure, coalescing numeric progress in bounded memory; no requirement for HTTP/1 simultaneous upload/response. Use ResponseController.Flush after each emitted bounded progress interval, no fixed Content-Length, application/x-git-receive-pack-result and no-cache. Never concatenate the whole response into c.Data. Pre-upload middleware/auth failures retain their existing sanitized HTTP behavior. Once response bytes begin, use valid Git framing/connection error behavior rather than try to replace the response with JSON/another HTTP status.

## Capability correctness and wire frames

Preserve the first command's NUL-separated capability tokens as a bounded parsed set, validate against the advertisement selected for that repository/session, and sign the resulting set in Begin. Do not discard tokens, hardcode sideband, or let unrecognized requested features silently change semantics. Unknown harmless tokens follow the owning Git protocol rule; unsupported required advertised modes must not be claimed. Reject malformed command/capability syntax and inconsistent multiple capability lists before publication.

Initial new-path modes implement report-status, side-band-64k, quiet, delete-refs and supported object-format/ref semantics. Advertise atomic only when the native publication path actually proves all-or-none behavior for that requested push; otherwise remove atomic from effective advertisements before accepting traffic on that version. Neither spec 075 nor source 074's per-ref partial recovery establishes atomic by itself. Do not advertise push-options until its extra section is genuinely parsed and bounded. Existing fetch/protocol-v2 capabilities remain separate.

| Negotiation / event | Wire projection |
| --- | --- |
| side-band-64k selected | Channel2 carries optional sanitized human progress; channel1 carries the inner report-status pkt-line byte stream. Each outer packet has4-byte hex length plus1-byte channel plus at most65,515 bytes payload (total<=65,520). |
| Final known ref status | Inner sequence: unpack ok/error and ok/ng per actual ref outcome, then inner0000; split its bytes across valid channel1 outer packets, then one outer0000. Normally emit completed status only after the required admission outcome; explicit detach/operational failure must not be labeled admission completion. |
| No sideband | Plain report-status pkt-lines/flush; no channel bytes, progress text, heartbeat or arbitrary report link inserted. Wait for admission just as negotiated clients do, then emit actual ref status; machine report lookup remains available by submitted repository/revision/authorized correlation. |
| quiet | Suppress optional progress/heartbeat and human diagnostic rendering; keep mandatory ref/error/status correctness. Quiet sideband and quiet non-sideband retain the default wait-for-admission policy; it must not depend on heartbeat to keep proxies alive. |
| Pre-receive rejection | Preserve actual rejected/uncommitted refs and bounded authorized diagnostic projection in negotiated mode. Do not create accepted PostReceive reports for proposed commits. |
| Committed refs, failed/pending admission | Optional channel2 admission summary/pending report reference, then actual ok ref status. No ng or channel3 fatal merely for post-commit admission failure. |
| Unknown publication / truncated transport | Do not emit invented complete status. Close with the supported transport error and preserve private operation identity for authorized source lookup; accepted source/work remains recoverable. |

Golden independent-client fixtures must check exact byte lengths, nested/outer flushes, empty/delete-only pushes, errors, mixed ref outcomes and no-sideband fallback. Packet65,520 is the negotiated side-band-64k ceiling from Git's protocol, not an assumed65,536 packet. Human output escapes control/terminal sequences and untrusted paths/messages.

## API-owned attached observation

After verified committed results, API ensures/reconciles accepted roots through execution-recovery.md and observes its own report state. Git does not poll/watch API reports on behalf of this HTTP session. Release all repository/publication guards before post-receive waiting. Internal observation uses the same durable state/journal semantics with current authorization, not a new public progress event service; intermediate updates may coalesce.

Pushes wait for their required post-receive admission outcomes by default; streaming makes that synchronous client experience visible while execution remains durable and independent. Quiet suppresses optional text; non-sideband omits unsupported human output. Neither mode silently opts out of waiting. There is no separate default observation timer or observation-only maximum. Explicit operator detach is an override, not the default. Custom git push options require real advertisement/parsing/allowlist/signing before support; no new option is claimed here.

At durable acceptance, emit bounded batch/report identity within 2 s under healthy qualified load; an earlier operation ID is correlation only. Keep the response attached and stream progress until required admission completes, including supported automatic recovery/retries. When execution reaches a configured processing limit or verified unresolved/paused disposition requiring intervention, report timeout/pending/uncertainty explicitly, not successful admission. Queue/execution/retry budgets are finite and define the effective supported wait; startup must reject proxy/write/idle limits too short for that end-to-end budget. The 300-second per-attempt execution deadline is not an observer cutoff and does not prevent waiting across a permitted retry.

Disconnect/explicit detach/slow-client transport failure or credential expiry/revocation ends or reauthorizes only observation. If the connection and authority permit, render a bounded outcome/pending report reference in negotiated nonquiet output, followed by actual ref status/flush. In every mode, do not turn already-committed refs into ng or treat a detached observer as completed admission. Expired authority suppresses further report details. No observer/request cancellation context controls accepted work or its recovery. Release repository/publication locks before waiting.

Bounds/API: <=64 observer sessions,64 KiB pending output/session,256 KiB total/session,<=10 coalesced updates/s and1 heartbeat/5 s; <=50 remote diagnostic lines/push, omission count/reference within output limits. Report findings persist independently. If total optional output is exhausted, stop optional output and continue waiting for admission; emit reserved truthful final protocol status only when the wait legitimately ends; reserve40 KiB of the total for terminal/status framing, with max 32 refs/refname<=1 KiB, rejection reason<=128 bytes and unpack reason<=512 bytes. Validate the worst-case framing budget before streaming; optional output uses only the remaining216 KiB. A slow socket has bounded write deadlines and is detached when it cannot drain; it cannot stall execution.

Proxy fixtures disable response buffering/compression that delays flushing; idle/write limits cover the configured end-to-end queue/execution/retry budget plus transport margin, including quiet/non-sideband sessions. Qualify a single-attempt 300-second execution wait with at least 330 s transport allowance and separately qualify the longer declared queue/retry budget; 330 s alone is not evidence for multiple attempts. Upload buffering must still preserve configured finite body/time limits. Test actual supported proxy and direct paths with quiet traffic and long pauses; heartbeats alone are not evidence of quiet compatibility.

## Selection, failure and rollout

Deploy native new RPC/receipt/guard support before enabling new API advertisement/route. Select new/legacy RPC through verified deployment capabilities or a side-effect-free method/version probe before consuming/sending push bytes. Existing InfoRefs is not by itself proof a particular streaming RPC is implemented. No transparent fallback/replay after any push transmission, Unimplemented with uncertain dispatch, or transport loss. Unsupported API/Git combinations remain legacy with honest capabilities, or unavailable; never advertise durable streaming through an incapable replica. Regenerate Go/Rust stubs together during implementation.

Primary sources: [Git capabilities and packet lengths](https://git-scm.com/docs/gitprotocol-capabilities), [report-status](https://git-scm.com/docs/gitprotocol-pack#_report_status), [Smart HTTP](https://git-scm.com/docs/gitprotocol-http). Existing receive-pack compatibility is tested separately; no request to implement SSH or protocol-v2 fetch.
