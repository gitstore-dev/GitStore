# Persistence and Recovery Contract (Proposed)

API owns Scylla/memdb state and asynchronous delivery-provider handoff/reconciliation. No webhook execution transport or controller-manager sender. Svix owns the production HTTP queue/retries; dev is explicitly process-local. New migrations follow query-first names and preserve applied migration history. Configure QUORUM/SERIAL semantics for new LWT authority; inspect every CAS result and close iterators. memdb implements the same state-machine contract but is not production durability evidence.

## 1. Event observation and exact series count

1. Authenticate/authorize producer binding and namespace UID, validate bounded immutable spec/body/reference facts and canonical hash. A namespace-UID/name claim binds one producerBindingUID/seriesUID/fingerprint; another producer or incompatible content conflicts. Persist a lifecycle control row in that series partition before first summary creation. It remains authoritative after summary deletion. Reject closed/expired/new-incarnation targets; never interpret an absent summary as a new series with the old UID.
2. Look up producer-scoped idempotency receipt; same key/different hash -> CONFLICT/IDEMPOTENCY_CONFLICT. A known APPLIED result returns its result while retained; if its Event expired, return FAILED_PRECONDITION/EVENT_EXPIRED rather than recreate it. Event names are not reusable in that namespace/producer for the retained receipt/recovery horizon.
3. Persist bounded pending intent in a minute/shard recovery partition **before** canonical receipt creation. The intent has request hash, canonical target and redacted content needed to retry; receipt create-if-absent pins the winning intent/series UID. Concurrent orphan intents compare the winner and are reclaimable. No receipt can be acknowledged or applied from an unenumerable transient queue.
4. Create/update series summary plus this observation's applied-marker and lifecycle version in one same-table/partition conditional batch. Initial summary/marker creation requires its uniquely initialized OPEN lifecycle; append checks OPEN/expected lifecycle+summary versions and deadline/count bounds. Summary stores complete envelope/count/expiry; control retains state/version/deadline independently. On conflict reload; a present matching marker means already applied. Internal control/marker changes are progress, not public Event mutations.
5. Persist receipt APPLIED/result identity. Only now return recordEvent.event. Crash after summary/marker but before receipt completion is repaired by marker inspection. Crash after preparation may leave outcome pending; return existing FAILED_PRECONDITION/RECORDING_PENDING and retry the same key, not a success-shaped provisional Event or confirmed rejection.
6. At count/lifetime boundary a new unapplied receipt becomes durably REJECTED_SERIES_CLOSED; no successful acknowledgement/count increment. Producer starts another name/key. A prior APPLIED receipt remains idempotent. Bound repair workers/batches and stop accepting when pending-intent quota is exhausted; diagnostics loss policy does not permit losing an already acknowledged materialization.

Due/list/UID indexes are recoverable projections. Before marking a summary mutation complete, persist the projection intent that makes its indexes repairable. Point reads verify canonical series state. Expiry conditionally closes lifecycle and deletes summary atomically within that same partition; retain control/name claim/markers through all receipt/intent horizons. A pending/new observation cannot reopen closed lifecycle. Do not rely on TTL for public delete or blindly delete a refreshed row.

Register one source adapter through existing RunCatalogCDC/source sequencing that understands summary/internal row discriminators. Current generic catalog extraction cannot safely decode applied-marker rows. Full-image summary CDC enters the existing shared journal. Typed and generic Event watches perform expiry/authorization checks; original journal cursor/bookmark/gap rules remain owning behavior.

## 2. Audit capture and required operation recovery

No public audit append API. Trusted request/command hooks build safe evidence from current authenticated context/canonical actions, preserving claimed versus verified actor and authenticated service versus initiator. No password/bearer/assertion/recovery data or arbitrary request snapshots. Actor strings are historical evidence, not a second mutable identity-directory model.

Initial policy: REQUIRED_PRE for RBAC, credential lifecycle, audit export, subscription configuration and manual replay; ASYNC_BOUNDED for failed authentication/authorization, ordinary reads and catalog completions. Configuration may strengthen coverage. If the owning command lacks recoverable outcome proof, required coverage stays unavailable and the protected operation fails before effects. No generic audit flag claims coverage for an unintegrated command.

Required path: persist enumerable operation intent -> append immutable Intent under deterministic stage identity -> execute the existing guarded/idempotent command -> verify outcome using its owned receipt/source state -> append distinct Completion/Uncertain evidence -> mark command recovered. Persisting intent is not proof of completion. If outcome append fails after effects, retain command/recovery state and expose uncertainty; do not return a fictitious rollback. Git completion can reference #139's verified mutation identity when that source exists; #501 remains admission outcome owner. Concurrent retries compare canonical intent, not mutable current resource names.

Async path: <=1,000 queued safe records/API, <=32 writes/API, <=5 s queued age, <=3 attempts within that age; explicit accepted/lost counters. It is not durable until append. Storage/index intent precedes evidence acknowledgement; immutable authoritative evidence remains queryable by its identity if a secondary index needs repair. Query/export requires audit-specific operator authority. Export creates a bounded audited command (<=10,000 records/run, <=24-hour range), returning pages through existing authorized transport; no public download URL or unlimited archive promise.

Audit store/bootstrap ownership must be ready before protected operations. Health/readiness, append/cleanup and internal recovery do not recursively require audit writes. Audit read policy is async bounded; export is required and cannot recurse into another export. No normal API bypass for emergency repair. Operator out-of-band recovery is documented separately and not called complete audit coverage.

## 3. Resource historical facts and outbox acceptance

Extend internal ResourceWatchEvent/source payload version additively with bounded private **safe transition facts**, produced from authoritative CDC images before discard: previous/current UID/resourceVersion/generation, deletion identity and registered material condition changes. Reuse existing canonical resource-reference semantics. Do not persist generic unrestricted prior bodies. Public resource DELETED.object remains null; private facts are not serialized by generic watch. Old records lacking necessary facts remain explicitly unsupported/gapped for that event type, not synthesized through current-object lookup.

Default extraction: opt-in supported catalog kinds and created/updated/deleted; updated ignores resourceVersion-only/bookkeeping changes, and conditionChanged emits only registered semantic condition transitions. Exclude Event/AuditLog/outbox/delivery/internal progress. Pin extractor version/content to source interval; replay of previously published facts compares digest and preserves identity. No blanket promise that every status patch is a business event.

API materializer uses bounded internal journal reads with <=1,000,000 retained replay records per recovery and explicit retention/epoch checks, rather than treating public subscriber MaxReplayEvents as an unlimited private queue. It reads <=128 source records/1 MiB under its **own keyed control row**, not the journal materializer lease. For each eligible source position:

1. Persist deterministic materialization intent and immutable outbox fact IF NOT EXISTS, comparing full digest on duplicate.
2. Resolve subscriptions through retained activation intervals at that position. Capture immutable route pages (<=32 entries/page, <=64 eligible subscriptions/namespace), pinned config revisions and total digest; seal manifest only when all pages are durable/recoverable.
3. Persist routing continuation and fact/manifest status. Source checkpoint may advance once this required work is recoverable; no need to wait for HTTP or every delivery row. Recovery can enumerate incomplete fact/manifest intents independently of source retention.
4. Router processes sealed manifest pages and calls EnsureDeliveryIfAbsent(eventUID, subscriptionUID), comparing pinned configuration digest. It records each completed route page before advancing its independent routing checkpoint.

Every multi-partition step has an immutable operation key/intent and replay verifier. CAS checks materializer/router version/fence on protected control updates. No cross-partition LOGGED BATCH or independent lease grants atomicity. Gaps persist a control record outside the missing source interval, set source/subscription Degraded and stop claims of contiguous history. Resource relist can repair current-state caches but never acknowledge missing occurrences.

## 4. Activation intervals and configuration safety

Git-backed EventSubscription admission validates source scope, export rights, registered extractor/filter schema, sink egress, SecretRef authorization, limits and proposed actions. Store immutable activation revisions. Before capturing any cut, install a per-source activation barrier by CAS, serialized against an outstanding manifest reservation. The barrier blocks new routing reservations while source high water is captured and interval rows are staged. Materializers reserve each manifest position/catalog revision at that same source control; they cannot seal using a stale interval revision. An old revision therefore cannot acquire N+1 before an activation later cuts it off at N.

Capture exclusive high-water marks per source; previous revision closes at those marks. Publish interval/catalog pointers and clear barriers only after the complete intended activation is durable. Before COMMITTING, abort can restore old intervals; after any source commit begins, recovery completes the same activation, not a fictional rollback. Multi-source commits have known separate cut points, not a globally atomic instant. <=16 concrete sources/subscription; Git sources bind repository UIDs, not dynamic name expansion. Incomplete activation remains unready and barrier recovery is enumerable.

Old work pins sink URI, subscription UID/config revision, approved source scope, secret binding, provider identity and effective policy version. Configuration edits cannot retarget existing deliveries. Recheck current authority before provider handoff/replay; material may rotate under the approved binding. Disable/revocation stops new handoffs/routes and requests provider disable; accepted work remains potentially deliverable until stop is confirmed. Deletion/namespace teardown records cancellation intent, retaining facts/history and exposing unconfirmed external cancellation. Same-name recreation has no claim to old work. No promise of per-attempt GitStore authorization checks inside Svix or recall of transmitted requests. Profiles requiring unsupported revocation guarantees remain unavailable.

## 5. Provider handoff, status and replay

Persist an enumerable handoff intent before calling a provider. Its deterministic key binds logical delivery/run UID, provider deployment/tenant, immutable destination revision, policy version and payload digest. State is Prepared -> Submitting -> Accepted, DefinitelyRejected or SubmissionUncertain. CAS/fence guards every transition and binds the provider receipt. Bounded bucket/shard indexes enumerate interrupted work; they are not send authority. No remote call and local write are claimed atomic.

After Accepted persist the provider message/destination receipt before completing the handoff. If the API crashes after remote acceptance or loses the response, recover through the same submission key and ReconcileSubmission. Retry only within proven provider deduplication guarantees. After the provider idempotency/lookup horizon, keep unresolved work Paused/SUBMISSION_UNCERTAIN for explicit audited recovery; do not blindly create another message or declare loss/success. Fencing protects local state but cannot undo a remote call by a stale API replica. Retain receipts through every recoverable run.

Source/routing progress requires durable facts/manifests/handoff obligations, not successful submission or HTTP completion. Routing preserves source-position provenance and enumerates every route before advancing; it does not promise serial receiver arrival. Svix performs accepted-message scheduling/retries. No production GitStore subscription-head send queue, shared HTTP permits or claim/prepare/complete protocol is required.

Poll bounded provider message/endpoint status with authenticated binding checks. Persist observation identity/version and terminal evidence before updating WebhookDelivery.status.resolved through expected-version CAS; duplicate observations are idempotent, stale observations cannot regress terminal state or overwrite another replay run. Acceptance is InFlight awaiting external completion, not proof an HTTP attempt occurred. Unknown attemptCount/nextAttemptAt stays null. Confirmed 2xx means receipt, not business completion. Retain <=12 safe latest attempt summaries/run and <=10 replay runs; terminal GitStore projection is backed by provider evidence, not an independent competing outcome log. Missing provider evidence sets a degraded condition and uncertainty.

Replay first persists an authorized/audited run intent with its own idempotency key, then calls Redeliver on the retained original message/destination. Resolve ambiguous replay acceptance before another call. Preserve the approved CloudEvent source/id/content and original outcome; record provider transport identity according to adapter capabilities. Missing payload/destination/provider retention yields REPLAY_EXPIRED, not synthetic replacement. Cancellation is terminal only with confirmation or proof no external submission could have occurred. Provider changes require an explicit drained/reconciled migration, never automatic failover.

See [delivery-provider.md](delivery-provider.md) for dev limitations, adapter operations, policy profiles and production qualification.

## 6. Source/control failure and overload

Use bounded named control rows for each source/materializer/router/subscription; reuse watchjournal CAS/fence patterns without sharing resource_watch_clock. A worker losing ownership stops scheduling; target checks still reject stale commands after a stall. Healthy grants/renewals are 30 s/10 s with bounded jitter; retry deadlines come from persisted state.

At storage quota high water, stop new acceptance at the correct boundary. A diagnostic producer may drop with counters; required audit may reject a protected operation before effects; Git source reserves log capacity before ref publication; outbox cannot drop accepted pending payload. If source history is lost before materialization, declare the gap and degraded coverage rather than extend retention without bound or pretend HTTP succeeded.
