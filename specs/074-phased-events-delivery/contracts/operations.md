# API, Authorization and Configuration Contract (Proposed)

[admin.graphqls](admin.graphqls) is an additive Admin overlay against current common/Admin schemas. It does not mount anything on Storefront. Shared helpers proposed by spec072 must converge in one canonical owner: ResourceNamespacePath has namespace/name; CatalogObjectReferenceInput adds optional UID; SecretRefInput mirrors the existing SecretRef. No duplicate definitions on integration. Shared status fields remain observedGeneration, lastAppliedRevision, conditions:[Condition!], resolved. Stored runtime resources implement Node with canonical envelope and body; AuditLog has no status. Mutation Payloads are control DTOs, not new resource envelopes.

## Recording and access

recordEvent accepts versioned immutable spec/body, required canonical metadata.name/namespace and a caller idempotency key <=128 bytes. Reject wrong version/kind, resourceVersion on create, oversized metadata/body and producer/reporting identity not bound to the principal. Input exposes no owner/UID/timestamps/status. Require captured regarding UID, explicit valid kind/name/scope; permit retained deleted references only under producer scope policy, without treating assertions as authoritative existence evidence. Same-name new resource UID cannot aggregate. Namespace-UID/name is claimed by one producer/series; another producer conflicts rather than creating an ambiguous namespacePath lookup. Optional report/related references use the same shared type and scope checks. Service subjects are cluster-scoped; namespace reach comes from bindings.

Markdown classification Normal/Warning maps to GraphQL NORMAL/WARNING through one canonical enum conversion; it does not change admission diagnostic severity. Per-observation reportingInstance and producer eventTime may differ without changing series identity; immutable Event.spec retains the first values, and receipts retain later provenance. An exact idempotent retry still preserves its complete original input. Caller chooses a stable series name for equivalent observations and a unique idempotency key per occurrence. Canonical spec/body/fingerprint is immutable; materially different explanation requires another name. Unknown reportingInstance patterns are rejected by the producer binding; its instance string cannot select a different logical producer. After count/lifetime closure start another name/key, not a silent alias/overwrite. A normal response returns the materialized Event; RECORDING_PENDING after preparation is an uncertain outcome and retry of the same key is safe. The 24-hour terminal receipt guarantee is finite: callers must never recycle old keys and cannot claim indefinite deduplication after retention. Event expiration yields EVENT_EXPIRED for retained retries, not resurrection.

Only service instrumentation appends AuditLog. Audit metadata belongs to the configured collector; actor/provider/initiator/service fields are captured evidence, not public write inputs or current-directory lookups. Canonical action is nullable before authentication/parsing/action resolution; do not fabricate membership in the finite catalog. Protected Intent/Completion stages require a known canonical action. Bootstrap validates collector identity/store before required protected operations. New subscription specs are admitted from the existing namespace gitstore-system repository using the ordinary resource/SecretRef/admission pipeline. No alternate direct-database registration endpoint. Config edits/delete still use that authority; desired admission does not imply successful source activation.

## Query/watch conventions

New connection fields accept first/after or last/before, namespace only for namespaced resources, and query. Default first50, max100; reject mixed directions, invalid/tampered/mismatched/expired cursors. Reuse one canonical cursor envelope binding API surface/kind, namespace UID, authorized context, normalized predicate/registry, fixed query time window and stable creation-time/UID order. A cursor is not authority; repeat current access checks. No exact totalCount or live cross-resource aggregates.

Initial independently shippable subset accepts blank/omitted query, lists retained namespace history, and bounds audit listing to the 24 hours ending at the first-page timestamp. Cursor carries that fixed end/window and registered index route. Nonblank query returns BAD_USER_INPUT/UNSUPPORTED_CAPABILITY until the owning shared query compiler/index subset from spec073 is actually implemented. There is no new per-kind filter dialect and no requirement to wait for its Storefront contract to reuse its shared foundations. Advertise only implemented terms via spec072 when that discovery endpoint exists; its absence does not grant capabilities. ExportAuditLogs is a bounded audited operation with explicit from/until (<=24 h), <=100/page and <=10,000/run, not a second query filter API or public object-store URL.

Point lookups and generic node(s) enforce the owning resource's action/disclosure rules. AuditLog is operator-only even through node; generic watchResources(AuditLog) is unsupported initially. watchEvents uses existing query/namespace/resourceVersion semantics; namespace omission requires fleet-wide Event watch authority. Typed and generic projections are from the same source, expire/filter consistently and preserve bookmarks/gap errors. Diagnostic history is recoverable only while retained. Outbox/delivery watches are not exposed in v1; API-internal provider reconciliation uses bounded indexed handoff intents instead.

EventSubscription backlog/dead-letter totals are asynchronously materialized into status.resolved, never counted live by resolvers. Staleness is explicit via observedAt/conditions. Delivery status also exposes observedAt for the last reconciled provider evidence; a missing observation remains null.

## Proposed action catalog additions

Add these finite actions to **shared/schemas/authorization-actions.json**, regenerate Go/Rust catalogs and add pluggable-provider tests. Entries below are proposals, not already granted permissions:

| Actions | Scope and authority |
| --- | --- |
| event.record/read/list/watch | Namespace; record requires producer binding, fleet watch additionally requires explicit cluster authority. |
| auditLog.read/list/export | Cluster, operator-only initially; export independently required/audited. |
| outboxEvent.read/list | Namespace, restricted integration operator; no public append. |
| eventSubscription.create/read/list/update/delete | Namespace; configuration also requires approved source export, egress and referenced secret authority. |
| webhookDelivery.read/list/replay | Namespace; replay separate from inspection and audited. |
| repository.events.watch | Namespace-scoped live repository source read, receiver-bound service RPC. |
| gitSource.replay | Cluster-scoped service recovery authority over retained closed-source repository UIDs, separately authorized/audited; no live-name fallback. |

Use the canonical action naming/generation schema and explicit cluster/fleet semantics; do not invent wildcard policy expansion or role-bearing tokens. Current selected AuthZ provider may reject unsupported new actions; feature readiness requires actual adapter support. Required audit coverage cannot be assumed for old binaries.

## Internal delivery provider boundary

API-internal Go operations manage provider destination binding, durable submission, status reconciliation and redelivery; see [delivery-provider.md](delivery-provider.md). The dev adapter is process-local; production requires Svix. No webhook execution commands, claim-token DTOs or worker actions are exposed through GraphQL, so this feature needs no SDL hiding machinery. Controller-manager keeps its existing reconciliation transport and gains no webhook sender.

Public mutation replayWebhookDelivery accepts an authorized/audited command, persists a separate run intent and returns its current projection/run identity. This response is not evidence of provider acceptance or successful redelivery. Use the same caller key to resolve uncertain command acceptance. Provider status is asynchronously materialized under CAS with observation provenance; duplicate/stale provider observations cannot regress outcomes. Unknown attempt counts remain null. Versioned operator profiles map subscription delivery policy to verified adapter capabilities; unsupported requirements fail activation.

## Errors

Reuse admission.Error.ToGQLError (code + diagnostics reason/message/level, optional field/file); existing FORBIDDEN stays sanitized without diagnostics. BAD_USER_INPUT covers INVALID_ENVELOPE, INVALID_FIELD, UNSUPPORTED_CAPABILITY and unsupported query/cursor input. CONFLICT covers IDEMPOTENCY_CONFLICT/RESOURCE_VERSION_CONFLICT/STALE_FENCE. FAILED_PRECONDITION covers RECORDING_PENDING, EVENT_SERIES_CLOSED, EVENT_EXPIRED, AUDIT_UNAVAILABLE, SOURCE_GAP, CONFIGURATION_UNAVAILABLE, SUBMISSION_UNCERTAIN and REPLAY_EXPIRED. Provider outages/status uncertainty use sanitized existing diagnostics and conditions; never return acceptance as delivery success. Preserve owning watch error codes. No new query-specific extension object or success-shaped failure. Error paths identify affected operation without leaking source/body/secret/destination details.

## Configuration/rollout

New settings live under existing api.events/api.audit/api.integrations (including delivery provider/profile configuration) and Git notification configuration owners, with existing Viper/environment mapping and no alias bypass. Record defaults/quotas/coverage policies in typed decoding tests. Event namespace overrides are operator-configured by namespace UID, constrained by cluster bounds; self-service editing is not part of v1. GitStore resolves secrets through existing file/env providers and generic secret-record/v1, separate from ServiceAccount assertion keys. Svix credential custody, endpoint signing-key provisioning/rotation and remote payload retention are explicitly configured and verified; no secret values are public GraphQL fields.

Deploy forward schema/store/provider adapters and generated public action support before activation; qualify Svix service/account capabilities, secret/tenant mappings and policy revisions. Production rejects the dev adapter. Bind pending runs to their original provider; no automatic failover. Keep new features inactive until all eligible recipients support required source/provider contract versions; use spec072 floors when implemented, otherwise explicit deployment role/version routing. New GraphQL types/RPCs are additive. Activate Event/Audit/Outbox/Git/Delivery independently. Source-driven admission stays off until the #501 handoff has one idempotent owner. Disable new acceptance, drain/recover work and preserve tables/segments/checkpoints before binary rollback; do not roll old Git writers against an enabled unresolved source log. No destructive down migration or pending-work deletion.
