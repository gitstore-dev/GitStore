# Retention, Expiry and Privacy (Proposed)

| Dimension | Initial policy | Contract |
| --- | --- | --- |
| Live Event visibility | Default 1 h; operator min/max 15 min/24 h; series max 24 h. | Server acceptance time, refresh bounded by first time +24 h. Explicit guarded delete; healthy cleanup <=60 s. |
| Event receipt/applied markers | >=24 h after terminal result and longer than any still-recoverable prepared receipt; quota bounded. | Do not delete a marker while any accepted/prepared work can reapply it. Closed/expired record remains non-live. |
| Resource source CDC | Existing fixed 14 d full images. | Includes protected Event content; not a one-hour erasure path. |
| Resource journal | Existing configured retention, default 7 d. | No longer-lived public live Event access; expiry-aware Event projection on typed/generic replay. Source postimages remain protected. |
| Git notification source | Default 24 h completed history, finite segment/byte quota. | Never trim unresolved intents; retention floor/epoch/gap explicit. Required new writes reject before effects if capacity cannot be reserved. |
| Audit | Operator policy, proposed fixture 30 d; no namespace override. | No ordinary delete/update API; explicit retention cleanup/export policy, not WORM/compliance certification. |
| Outbox/configuration | Pin while routing or any delivery is pending; then >=7 d replay retention after last terminal outcome. | No TTL erasure of pending accepted work. Storage exhaustion stops acceptance at the declared boundary; unresolved work requires operator action under policy. |
| Delivery/attempt/replay | Pending until terminal/explicit cancellation; terminal retained 7 d, bounded summaries/runs. | History cleanup cannot invalidate a retained replay promise. Production profiles require matching provider message/destination retention; expired provider or local material returns REPLAY_EXPIRED. Keep acceptance/status receipts through unresolved handoff/replay and do not re-create an expired provider message as historical redelivery. |

Svix retains submitted safe payloads and endpoint signing material outside GitStore. Operator policy must include provider retention/deletion, service location/access and replay availability, including confirmed remote cleanup. Local deletion alone is not proof of remote erasure. Dev queue retention/durability is process-local as declared by its capabilities.

One-hour Event TTL is **live diagnostic availability**, not physical privacy deletion. Full-image CDC/postimages may remain for their declared protected windows, including a final image after expiry. Retention policy validation includes every copy and backup/export policy; it rejects a stricter content-deletion promise this implementation cannot satisfy. No silent encryption/key-erasure claim. Source-redact prohibited secrets and minimize retained explanation fields.

Operator configuration under existing api configuration ownership defines Event defaults/bounds, per-namespace-UID overrides, recording quotas, audit coverage/retention, source retention and integration storage limits. v1 editing is operator-only; no parallel namespace-policy resource or self-service mutation. Namespace admins see effective Event expiry but cannot exceed operator constraints. Configuration revisions affect new series; existing series keep the pinned effective TTL/max lifetime, while security revocation still applies immediately. This prospective rule avoids retroactive expiry races. Namespace deletion stops new recording and delivery activation; existing private records remain bound to the old UID and are retained/cancelled according to explicit policy, never inherited by a same-name namespace.

Expiry work reads due index pages <=100 under bounded workers. Before deleting an Event summary, compare namespace/series UID, expected resourceVersion, deadline and terminal receipt constraints; stale entries are repaired, not trusted. CDC summary deletion produces the existing payload-free DELETED watch event. Generic/typed Event replay checks current expiry before exposing historical full payload; suppressed expired records still permit journal progress/bookmarks. Do not fabricate an ADDED live object after its expiry. Missing/expired cursors retain current WATCH_EXPIRED semantics.

Audit/outbox/delivery are excluded from generic diagnostic recording and default integration sources to prevent recursion. Public AuditLog watch is unsupported initially. A gap/control row is retained in the integration-source control partition independently of the missing source interval; it can report lost coverage even if the original journal history has gone. A relist repairs state, not historical delivery promises.

Quota enforcement uses persistent allocation/control state where correctness depends on the cap; per-process approximations may throttle earlier but cannot enlarge promised storage. Initial hard budgets are declared in [capacity acceptance](capacity-acceptance.md). Warn before high water; do not erase accepted pending work to free capacity. Mandatory operation/audit/source persistence fails at a truthful pre-effect boundary; post-effect failure is recoverable uncertainty. Diagnostic rejection is best effort to its producer and never rejects that producer's unrelated primary operation.
